## What is original, and what is derived

The operational House input is `data/processed/house_extracted.csv`, generated by `scripts/house.py` from this repository's 515 primary PDFs, pinned parser, ticker-cleaning code, and `data/review/decisions.json`. P3 runs the bundled extraction in its own workspace, verifies every primary PDF and parser file, checks each review's original evidence, and records the result in `data/processed/house_extraction.json`. The local review replay changes two amount-value cells without removing rows or replacing source text.

`data/raw/house_transactions_p2.csv` remains an untouched historical **derived** reference, not a table loaded by the integration pipeline. Its placement in the preserved archive does not make it official House CSV data. A full PDF rebuild independently reproduces the 7,667 report identities and all House fields feeding P3's comparison. Previous projects are the provenance of the captured archive and inherited code; neither checkout is needed at runtime.

The generated House cache records fingerprints for the PDF inventory, pinned parser, local extraction scripts, review rules, and output CSV. Missing or outdated output is regenerated; an altered cached CSV is rejected. `python scripts/house.py --rebuild` forces a new workspace and a complete extraction. Byte-preserving Git attributes keep the fingerprinted recipe, review inputs, and cached CSV valid across operating-system checkouts.

Senate HTML under `data/raw/senate/html/` is the original page content archived by the prior scraper. The new strict parser reads it locally; its 5,069 report/item identities reconcile to the bundled upstream table. The upstream parser stores the source ticker placeholder `--` as blank in 1,625 rows; P3 preserves the placeholder and normalizes only this documented representation difference during reconciliation. Other compared source fields match exactly.

The metadata's October 22, 2026 collection timestamp and 2021–2026 filing window belong to the source archive, not to P3's 2025 transaction-year population. House uses the earlier P2 archive. These are unequal snapshots.

`provenance/raw_sha256.json` records fingerprints for all 1,105 original P3 inputs; `verify_raw()` verifies every file before building. The HTTP cache stores raw response bodies and safe metadata separately. Windows Git checkout line endings and raw GitHub response line endings can differ for text; separate transport checksums document this difference without changing a raw file.

## Source visualization

The initial House WebP examples and coordinate records were copied from P2's source inspector. They show actual PDF pages. P3 verifies the underlying PDFs and pinned parser, refreshes displayed values from its own generated House extract, and can regenerate rectangles with its bundled observer. The website displays exact code from the bundled parser and current scripts, with line references generated from the local AST.

The source picker includes all 449 parsed House filings in the captured 2025 filing-index collection and all 583 captured electronic Senate filings across their saved dates. It is not a census of all official 2025 disclosures. The other 66 House PDFs remain in raw inputs without interactive parsed examples. The ticker-month comparison uses 2025 transaction dates.

`scripts/build_house_geometry.py` uses the bundled AST observer in `scripts/trace_geometry.py` to record every accepted transaction row on each displayed House PDF page, with coordinates cached under `docs/data/house_geometry/`. Counts are checked against P3's own extraction and the captured page metadata. Version-2 coordinate caches carry the fingerprint of P3's generated extract; structured values come from that extract. The normal site build synchronizes these values automatically. Original raw files and pinned parser code are not changed. Matched first-page filer name, status and state/district text can also be inspected.

All eight House table columns are hoverable, including notification date. The capital-gains and printed item-ID cells are marked as source-only: geometry clips their text, but the parser does not export a structured checkbox state or separate printed-ID value. Empty extracted text is not labeled unchecked. The generated sequential transaction number is explained separately. Senate views make every collected cell on every row hoverable without executing the original page scripts. Download links reference complete local sources. Random selection does not trigger live collection.

The field walkthroughs include complete source files, with step focus targets resolved from the Python AST and plain-English notes checked against literal source anchors. A missing or ambiguous anchor fails the build. The code pane initially jumps to those targets but can scroll through the entire file; Back to highlighted lines restores the step. Left/right navigation follows the PDF functions, P3's own extraction/cache implementation, and the shared-schema mapping. The independent rebuild retains the existing analysis population and join.

The processed CSVs and `docs/data/project.js` are generated outputs. The combined transaction file is an append preserving chamber and source identities. `combined_ticker_month.csv` is the separately validated one-to-one outer join. No amount range is turned into a made-up exact value.

No third-party license is invented for the inherited code; the source attribution and original vendor notes are retained. The two original portfolio QMD files are archival references, not independent executable P3 pages.
